# Tasks: Transactional Outbox for Payment Events

**Input**: Design documents from `specs/007-transactional-outbox/`.

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/outbound-events.md
and quickstart.md, all present. Constitution v1.3.0.

**Tests**: Included and REQUIRED. Constitution Principles IV and V require them, and
quickstart.md maps each scenario to a test.

**Organization**: grouped by the user stories in spec.md:
- US1: a recorded outcome is always announced, even after a crash (P1).
- US2: announcements are prompt (P1).
- US3: announcements arrive in order per payment (P2).

**No Setup phase**: there are no new projects or packages.

**Quality gate**: after **every** task, run in order (Constitution VIII; Docker must be running):
1. `dotnet build`
2. `dotnet format --verify-no-changes`
3. `dotnet test`

**Commits**: Conventional Commits scoped `US-07`.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: can run in parallel (different files, no dependency on an incomplete task).
- **[Story]**: US1, US2 or US3.
- **(new)**: the file does not exist yet. **(rename)**: use `git mv`, then edit.

## Phase 4: User Story 3: announcements arrive in order per payment (P2)

payment does not block other payments.

**Independent Test**: the processed entry for payment P fails while P is refunded. Once
delivery recovers, the processed message is consumed before the refunded one.
